# OpenAI Docs Korean Community

This repository is a community MVP for evaluating Korean translation quality against official OpenAI English-Korean page pairs.

The current goal is not to build a full translation platform. The goal is to validate a practical evaluation framework on a clear official EN-KO reference pair first, then extend the same framework to more difficult cases where Korean references are limited.

Codex is used in this repo for:

- first-pass candidate generation
- rewrite and evaluation workflow support
- report generation and future agent-loop experimentation

## Why This MVP Starts With Official EN-KO Pairs

Phase 1 intentionally starts with official `openai.com` English-Korean page pairs because they provide a clean reference path:

- `source_en` is the official English page
- `reference_ko` is the official Korean page

That makes it easier to validate alignment, scoring, reporting, and human-review rules before moving to `developers.openai.com`, where Korean references are often unavailable.

## Phase Scope

### Phase 1 MVP

Phase 1 is the current main path.

Workflow:

1. collect an official EN-KO page pair
2. align paragraph-level units
3. generate `candidate_ko` with `gpt-5.5`
4. rewrite to `improved_candidate_ko` with `gpt-5.5`
5. evaluate either `candidate_ko` or `improved_candidate_ko` against `reference_ko`
6. review selected items manually
7. promote only approved items into a small `reviewed_golden` subset

Current demo pair:

- English: [why-we-no-longer-evaluate-swe-bench-verified](https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/)
- Korean: [why-we-no-longer-evaluate-swe-bench-verified (ko-KR)](https://openai.com/ko-KR/index/why-we-no-longer-evaluate-swe-bench-verified/)

### Phase 2 Expansion

Phase 2 is intentionally separate from the current MVP.

Planned direction:

- expand to `developers.openai.com`
- support documents with limited or missing Korean references
- rely more on reference-less evaluation and community review
- grow the reviewed-golden pool over time

## Core Data Roles

| Role | Meaning |
| --- | --- |
| `source_en` | Official English source text |
| `reference_ko` | Official Korean reference used for Phase 1 pair evaluation |
| `candidate_ko` | First-pass Korean translation generated by `gpt-5.5` |
| `improved_candidate_ko` | Rewrite candidate generated by `gpt-5.5` |
| `reviewed_golden` | Small human-approved evaluation target used for lightweight regression checks and future comparison |

Important rules:

- `reference_ko` is a baseline for Phase 1 pair evaluation. It is not automatically golden.
- `candidate_ko` is never stored as golden.
- `improved_candidate_ko` is still only a candidate. It is never automatically golden.
- only human-reviewed items can be promoted to `reviewed_golden`

## Two-Stage Translation Pipeline

The repository supports a two-stage translation flow:

- `gpt-5.5` with the first-pass translation prompt for `candidate_ko`
- `gpt-5.5` with the rewrite/refinement prompt for `improved_candidate_ko`

The stages remain separate so reviewers can compare:

- first-pass vs improved output
- different prompts
- different pipeline labels
- future model or workflow variants

Recommended current MVP configuration:

- `generation_model`: `gpt-5.5`
- `rewrite_model`: `gpt-5.5`
- `backtranslation_model`: `gpt-5.5`
- `judge_model`: `gpt-5.5`
- `embedding_model`: `text-embedding-3-small`

## Evaluation Framing

The repo uses two compatible evaluation layers.

### 1. Phase 1 Pair Evaluation

This is the main MVP path.

- compare `candidate_ko` or `improved_candidate_ko` against `reference_ko`
- compute Korean-side cosine similarity
- compute source-vs-backtranslation similarity
- compute terminology consistency
- use an LLM judge for additional quality signals
- build a markdown report

### 2. Lightweight Golden Evaluation

This is a smaller reviewed-golden layer under [docs/golden/README.md](docs/golden/README.md).

For the current review-ready Phase 1 MVP, the active golden records come only from the official `openai.com` EN-KO pair review. Developer-document examples have been removed from the active golden set and can be reintroduced later in Phase 2.

Current golden file state:

- `words.json`: preserved as an empty placeholder
- `sentences.json`: preserved as an empty placeholder
- `paragraphs.json`: contains the approved reviewed-golden subset from `reviews/phase1_pair_review.md`

`run_golden_eval.py` currently has active targets for `--golden-set paragraphs`. Word- and sentence-level targets should be added later from official page-pair review, not from the older Developer-document example bank.

## Human Review

Human review remains the final approval layer.

- the review worksheet is [reviews/phase1_pair_review.md](reviews/phase1_pair_review.md)
- it records `source_en`, `reference_ko`, `candidate_ko`, `improved_candidate_ko`, decisions, approved reviewed Korean text, and notes
- the worksheet is the source of truth for the current approved paragraph-level reviewed subset
- promoted reviewed examples are reflected in [docs/golden/paragraphs.json](docs/golden/paragraphs.json)

This means the flow is:

`source_en -> candidate_ko -> improved_candidate_ko -> evaluation -> human review -> reviewed_golden`

## Recommended Command Sequence

Requirements:

- Python 3.11+
- Chrome
- `OPENAI_API_KEY`
- `pip install -r requirements.txt`

Example commands:

```powershell
python -X utf8 collect_pair.py --slug why-we-no-longer-evaluate-swe-bench-verified --source-url https://openai.com/index/why-we-no-longer-evaluate-swe-bench-verified/ --reference-url https://openai.com/ko-KR/index/why-we-no-longer-evaluate-swe-bench-verified/
python -X utf8 align_units.py --slug why-we-no-longer-evaluate-swe-bench-verified
python -X utf8 generate_candidate.py --input data/processed/why-we-no-longer-evaluate-swe-bench-verified.aligned.json --model gpt-5.5
python -X utf8 run_eval.py --input data/processed/why-we-no-longer-evaluate-swe-bench-verified.aligned.candidates.json --candidate-field candidate_ko --backtranslation-model gpt-5.5 --judge-model gpt-5.5 --embedding-model text-embedding-3-small --output reports/why-we-no-longer-evaluate-swe-bench-verified.aligned.candidates.eval.json
python -X utf8 improve_candidate.py --input data/processed/why-we-no-longer-evaluate-swe-bench-verified.aligned.candidates.json --eval-input reports/why-we-no-longer-evaluate-swe-bench-verified.aligned.candidates.eval.json --model gpt-5.5 --output data/processed/why-we-no-longer-evaluate-swe-bench-verified.aligned.candidates.improved.json
python -X utf8 run_eval.py --input data/processed/why-we-no-longer-evaluate-swe-bench-verified.aligned.candidates.improved.json --candidate-field improved_candidate_ko --backtranslation-model gpt-5.5 --judge-model gpt-5.5 --embedding-model text-embedding-3-small --output reports/why-we-no-longer-evaluate-swe-bench-verified.aligned.candidates.improved.eval.json
python -X utf8 build_report.py --input reports/why-we-no-longer-evaluate-swe-bench-verified.aligned.candidates.improved.eval.json --compare-input reports/why-we-no-longer-evaluate-swe-bench-verified.aligned.candidates.eval.json --output reports/why-we-no-longer-evaluate-swe-bench-verified.report.md
```

On Windows you can use `py -3 -X utf8` or a full Python path instead of `python`.
